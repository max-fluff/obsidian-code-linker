# Community listing

What goes on the plugin's page in the community catalog. Kept here so the next release can
diff it instead of guessing what is live. The short description must match `manifest.json`
and the entry in `obsidianmd/obsidian-releases`.

## Short

Autocomplete references to source-code files and types, inserting a deep-link that opens the file at its line in your editor, or embedding the snippet inline with its own line numbers.

## Long

Code Linker turns the names you already write — a class, a function, a file — into links that open the file at the exact line in your editor.

**Autocomplete by name.** Type the trigger and a fuzzy query: `hc` finds `HttpClient`. The index holds file names plus type declarations with their line numbers, so a suggestion drops you on the declaration rather than the top of the file. Suggestions stay out of code blocks, frontmatter and existing links.

**Open where you work.** Presets for VS Code, JetBrains, plain `file://`, and GitHub and GitLab permalinks to the exact commit — plus URL templates of your own for anything else (Cursor, PyCharm, Sublime). What lands in the note is a plain markdown link carrying a portable `{root}` path, so the same vault works on another machine that keeps the repository somewhere else.

**Read the code in the note.** A `code-link` block renders a snippet inline: numbered by its lines in the file, the declaration highlighted, and a strip above and below that opens out a few more lines when you want them. The block keeps saying what it said — opening it out is a way of reading, not an edit.

**Links that survive a refactor.** Pin a link to a symbol, to a kind of declaration, or to the exact line, and it is checked against the index. When the code moves, the link is marked and repaired in place — one note or the whole vault, with a preview before anything is written.

**Index what you want.** Nine languages out of the box, each with its own entity kinds, all switchable. `.gitignore` is respected, so build output never reaches the index.

Desktop only: it reads files from disk through Node's filesystem API, which isn't available on mobile.
